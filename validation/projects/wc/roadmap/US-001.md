# User Story 001: Core wc counting (lines, words, bytes) for a single file or stdin

As a CLI user,
I want to count the number of lines, words, and bytes in a file or from standard input,
So that I can analyze the basic size metrics of my text input.

## Requirements

### 1. Basic Counting Options
The program must support the following command-line flags:
- `-l` / `--lines`: Count the number of newlines (`'\n'`).
- `-w` / `--words`: Count the number of words (non-empty sequences of characters delimited by whitespace).
- `-c` / `--bytes`: Count the number of bytes.

### 2. Default Behavior
- If no options are specified, the program should default to counting lines, words, and bytes (equivalent to `-l -w -c`).

### 3. Input Sources
- **Single File:** Read from a specified file (e.g., `wc file.txt`). Output format must print the counts followed by the filename.
- **Standard Input (stdin):** If no files are specified, or if the filename is `-`, read from stdin. Output format must print the counts only (no filename).

### 4. Output Formatting
- Counts must be separated by one or more spaces, right-aligned in columns of width 8.
- Example: `      10       45      280 file.txt`

### 5. Architectural & Performance Constraints
- **No Unsafe Code:** The code must include `#![deny(unsafe_code)]` at the crate root.
- **DDD & SOLID:** Organize the codebase into Domain, Application, and Infrastructure layers. Ensure dependencies are inverted (e.g. inject dependencies via constructors/traits).
- **Streaming I/O:** Implement buffered, chunked reading (e.g., using `BufReader`) to allow processing files of several gigabytes without exceeding a minimal constant memory overhead.

## Validation Criteria

### Unit Tests (With Mocking)
- Verify character, word, and line count logic on raw buffers/streams using mock inputs.
- Test edge cases: empty input, single word, inputs with multiple spaces/newlines.

### Integration Tests (No Mocking)
- Run the compiled binary as a subprocess.
- Verify output formatting and correctness when processing a file or piping standard input.
- Verify memory consumption remains constant when running the tool on a large generated input stream.
