# User Story 001: Core wc counting (lines, words, bytes) for a single file or stdin

As a CLI user,
I want to count the number of lines, words, and bytes in a file or from standard input,
So that I can analyze the basic size metrics of my text input.

## Requirements

### 1. Basic Counting Options
The program must support the following command-line flags (parsed via `clap` v4 derive per SPEC §1.1):
- `-l` / `--lines`: Count the number of newlines (`'\n'`).
- `-w` / `--words`: Count the number of words (non-empty sequences of characters delimited by whitespace; whitespace = Rust `char::is_whitespace` per SPEC §3.4).
- `-c` / `--bytes`: Count the number of bytes.
- Short flags may be bundled (e.g. `-lw` == `-l -w`) per SPEC §3.1.

### 2. Default Behavior
- If no options are specified, the program should default to counting lines, words, and bytes (equivalent to `-l -w -c`).

### 3. Input Sources
- **Single File:** Read from a specified file (e.g., `wc file.txt`). Output format must print the counts followed by the filename.
- **Standard Input (stdin):** If no files are specified, or if the filename is `-`, read from stdin. Output format must print the counts only (no filename).

### 4. Output Formatting
- Per SPEC §3.3: counts in canonical order `lines, words, bytes` (filtered to active flags, independent of flag order), each formatted `format!("{:>7}", n)`, separated by a single space; filename preceded by a single space if shown; no filename (and no trailing space) for stdin.
- Example expected stdout as a Rust string literal: `"      10       45      280 file.txt\n"`.

### 5. Architectural & Performance Constraints
- **No Unsafe Code:** The code must include `#![deny(unsafe_code)]` at the crate root.
- **DDD & SOLID:** Organize the codebase into Domain, Application, and Infrastructure layers. Ensure dependencies are inverted (e.g. inject dependencies via constructors/traits). `CountUseCase` receives `Box<dyn Read>` via its constructor (DIP).
- **Streaming I/O:** Implement buffered, chunked reading (e.g., using `BufReader` with 64–128 KB chunks) to allow processing files of several gigabytes without exceeding a minimal constant memory overhead.

## Validation Criteria

### Unit Tests (Rust `#[test]`, no mocking framework)
- Test `CountStrategy` implementations directly with `std::io::Cursor::new(b"...")` and assert exact `CountStats` fields.
- Cases (assert these exact values):
  - `b""`           → lines=0 words=0 bytes=0
  - `b"\n"`         → lines=1 words=0 bytes=1
  - `b"hello world"` → lines=0 words=2 bytes=11
  - `b"a  b\n\nc\n"` → lines=2 words=3 bytes=8
  - `b"  \n  \t\n"`  → lines=2 words=0 bytes=6
- Verify `CountUseCase` injects `Box<dyn Read>` via constructor (DIP) and returns the strategy's `CountStats`.

### Integration Tests (`assert_cmd` + `tempfile`, no mocking)
- Use `Command::cargo_bin("wc")` + `tempfile::NamedTempFile`.
- Assert byte-exact stdout for: file default, stdin default, `wc - file`, `wc -l file`, `wc -w -c file` (canonical column order `lines, words, bytes` — so `-w -c` emits `words` then `bytes`, regardless of flag order).
- Assert exit code 0 for all happy cases.
- Large-file test (see SPEC §5.2): 1 GB `yes 'a b c' | head -c 1G | cargo run --` stream, assert exit 0 and (if available) peak RSS < 50 MB via `/usr/bin/time -l` (Linux) or `/usr/bin/time -v` (macOS); otherwise assert exit 0 and wall-time < 60 s.
