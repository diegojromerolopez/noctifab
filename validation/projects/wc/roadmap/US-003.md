# User Story 003: Multi-file support with total counts summary

As a CLI user,
I want to run wc on multiple files at once
So that I can see the metrics for each file and get an aggregate total of all files.

## Requirements

### 1. Sequential Processing
- Accept multiple file paths as arguments (e.g. `wc file1.txt file2.txt`).
- Process and output counts for each file sequentially in the order specified.

### 2. Total Row
- After all files, print an additional line with accumulated totals followed by `total`.
- Print the `total` row only when ≥2 input sources are processed. A single file or stdin alone does NOT produce a `total` row.
- If some files fail and some succeed, the total is computed from **successful files only**. Print the total row if ≥2 files were successfully processed.
- If every input failed, print no stdout at all and exit 1.

### 3. Mixing Stdin and Files
- If the argument list contains `-`, read from stdin for that entry. Output name is `-`.

### 4. Aggregation
- `lines`, `words`, `chars`, `bytes`: total = sum across files.
- `max_line_length`: total = max across files (not sum).
- Missing/unreadable files do NOT contribute to totals and do NOT appear on stdout.

### 5. Output Format
Running `wc -l -w file1.txt file2.txt` (each number is `{:>7}`, space-separated, then space before name):
```
     10       45 file1.txt
      5       20 file2.txt
     15       65 total
```

### 6. Architectural & Performance Constraints
- DDD & SOLID per SPEC §2.1. File orchestration belongs in the Application layer.
- Streaming I/O: memory must not accumulate with file count or file size.

## Implementation Hints

### Accumulation
Add an `accumulate(&mut self, other: &CountStats)` method on `CountStats` that sums numeric fields and takes the max for `max_line_len`. This is simpler than a full strategy-pattern abstraction and sufficient for the requirements.

## Validation Criteria

### Unit Tests
- Test `CountStats::accumulate`: create two stats with known values, accumulate, assert sums (and max for `max_line_len`).

### Integration Tests (No Mocking)
- Run the compiled binary with multiple temp files.
- Verify correct `total` row calculation and formatting.
- Verify single-file does NOT produce a `total` row.
- Verify mixed file and stdin (`-`) scenarios.
