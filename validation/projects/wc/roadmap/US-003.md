# User Story 003: UTF-8 characters count, maximum line length, and error handling

As a CLI user,
I want to count characters and max line length, and have standard error output for missing files/invalid options,
So that I can analyze non-ASCII files and get robust error feedback.

## Requirements

### 1. Character Counting
- Flag: `-m` / `--chars`
- Behavior: Counts the number of valid UTF-8 characters (codepoints). Note that a single UTF-8 character (e.g. `世`) can span multiple bytes.

### 2. Maximum Line Length
- Flag: `-L` / `--max-line-length`
- Behavior: Counts the number of UTF-8 characters in the longest line of the file (excluding the trailing newline character `\n`). If multiple files are processed, the `total` row should print the maximum line length found across all files.

### 3. File Missing Errors
- If a specified file does not exist, print an error message (e.g., `wc: <filename>: No such file or directory`) to `stderr`.
- The program must continue processing the remaining files in the list.
- The program must exit with a non-zero exit code (e.g. `1`) at the end if any file processing failed.

### 4. Invalid Options
- If an unsupported flag is provided (e.g. `wc --invalid`), print a usage/error message to `stderr` and exit immediately with a non-zero exit code.

### 5. Architectural & Performance Constraints
- **No Unsafe Code:** The code must include `#![deny(unsafe_code)]` at the crate root.
- **DDD & SOLID:** Maintain decoupling in the domain logic. For example, a `LineLengthTracker` or `UTF8CharCounter` should be isolated strategies conforming to standard counting traits.
- **Streaming I/O:** Track the length of lines on-the-fly inside the buffered stream loop without storing entire lines in memory.

## Validation Criteria

### Unit Tests (With Mocking)
- Verify character counting handles multi-byte characters and invalid UTF-8 sequences.
- Verify maximum line length calculation on custom test inputs (e.g., lines with emojis or tabs).

### Integration Tests (No Mocking)
- Run the compiled binary as a subprocess.
- Verify stdout and stderr outputs, and exit codes for invalid options and missing files.
- Verify execution on large input streams (e.g. piping 1GB+ generated streams) to confirm memory usage remains constant ($O(1)$) and does not leak or crash.
