# User Story 004: UTF-8 characters count, maximum line length, and error handling

As a CLI user,
I want to count characters and max line length, and have standard error output for missing files/invalid options,
So that I can analyze non-ASCII files and get robust error feedback.

## Requirements

### 1. Character Counting
- Flag: `-m` / `--chars`
- Behavior: Counts Unicode codepoints decoded from valid UTF-8. On an invalid byte sequence, count one codepoint per byte and continue (do not abort, do not error). Matches GNU `wc` `mbrtowc` fallback. Empty input → 0 chars.

### 2. Maximum Line Length
- Flag: `-L` / `--max-line-length`
- Behavior: Counts the number of UTF-8 characters (codepoints) in the longest line of the file (excluding the trailing `'\n'`). If multiple files are processed, the `total` row prints the maximum line length found across all files.
- A trailing `'\r'` in a `\r\n` line IS counted toward that line's length. A final line with no `'\n'` still contributes its length toward the maximum. Empty input → max line length = 0.

### 3. File Missing Errors
- If a specified file does not exist, write to stderr exactly `wc: <name>: <os error display>\n` (per SPEC §3.5), continue processing the remaining files in the list.
- Missing files do NOT appear on stdout and do NOT contribute to `total`.
- The program must exit with code **1** at the end if any file processing failed.

### 4. Invalid Options
- If an unsupported flag is provided (e.g. `wc --invalid`), write to stderr exactly `wc: invalid option -- '<char>'\nTry 'wc --help' for more information.\n` (per SPEC §3.5) and exit immediately with code **2**.
- All error messages use the literal program name `wc` (not `argv[0]`).

### 5. Architectural & Performance Constraints
- **No Unsafe Code:** The code must include `#![deny(unsafe_code)]` at the crate root.
- **DDD & SOLID:** Maintain decoupling in the domain logic. For example, a `LineLengthTracker` or `UTF8CharCounter` should be isolated strategies conforming to standard counting traits.
- **Streaming I/O:** Track the length of lines on-the-fly inside the buffered stream loop without storing entire lines in memory.

## Validation Criteria

### Unit Tests (Rust `#[test]`)
- Assert: `Cursor::new(b"a\xff\xcfz")` → chars = 4, bytes = 4 (invalid bytes counted 1 codepoint/byte).
- Assert: `Cursor::new("a\u{1F600}b")` → chars = 3, max_line_length = 3 (emoji is one codepoint).
- Assert: `Cursor::new("hi\r\nworld\n")` → max_line_length = 5 (`"world"`; the `\r` on the first line counts toward length 3 → `"hi\r"` = 3, so max is 5).
- Assert: `Cursor::new(b"")` → chars = 0, max_line_length = 0.

### Integration Tests (`assert_cmd` + `tempfile`)
- Run the compiled binary as a subprocess.
- Verify stdout byte-exact and exit code 0 for `-m`, `-L`, and `-c -m` (canonical order chars then bytes).
- Verify stderr byte-exact for missing file: `wc: <name>: No such file or directory\n` (or equivalent OS display), exit code 1, and that the missing file does NOT appear on stdout.
- Verify stderr byte-exact for invalid option: `wc: invalid option -- 'q'\nTry 'wc --help' for more information.\n`, exit code 2.
- Verify execution on large input streams (e.g. piping 1GB+ generated streams) to confirm memory usage remains constant O(1) and does not leak or crash (per SPEC §5.2 measurement mechanism).
