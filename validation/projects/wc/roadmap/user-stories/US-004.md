# User Story 004: UTF-8 characters count, maximum line length, and error handling

As a CLI user,
I want to count characters and max line length, and have standard error output for missing files/invalid options,
So that I can analyze non-ASCII files and get robust error feedback.

## Requirements

### 1. Character Counting (`-m` / `--chars`)
- Counts Unicode codepoints decoded from valid UTF-8.
- On an invalid byte sequence, count one codepoint **per invalid byte** and continue (do not abort, do not error). This matches GNU `wc` `mbrtowc` fallback behavior.
- Empty input → 0 chars.

### 2. Maximum Line Length (`-L` / `--max-line-length`)
- Reports the character count (Unicode codepoints) of the longest line, excluding the trailing `'\n'`.
- Lines are split ONLY on `'\n'`. A `'\r'` character is a regular character that counts toward line length.
- A final line with no trailing `'\n'` still contributes to the maximum.
- For multi-file: the `total` row shows the max across all files (not the sum).
- Empty input → 0.

### 3. File Missing Errors
- If a file doesn't exist or is unreadable: write `wc: <name>: <os error display>\n` to stderr, continue processing, exit 1.
- Missing files do NOT appear on stdout and do NOT contribute to `total`.

### 4. Invalid Options
- If an unsupported flag is provided (e.g. `wc -q`): write to stderr exactly:
  ```
  wc: invalid option -- '<char>'
  Try 'wc --help' for more information.
  ```
  Exit immediately with code **2**. All error messages use the literal program name `wc`.

### 5. Canonical Column Order
Output columns follow the canonical order: **lines, words, chars, bytes, max_line_length** — filtered to active flags. The `is_default()` logic must now account for `-m` and `-L` (if any flag is set, defaults are off).

## Implementation Hints

### Extend `StreamCounter`, do not create new strategies
Modify the existing `StreamCounter` to compute all five metrics (lines, words, chars, bytes, max_line_len) in the same single pass. The flags control only what gets printed, not what gets computed.

### UTF-8 fallback: do NOT use `String::from_utf8_lossy()`
`from_utf8_lossy` replaces each invalid byte **sequence** with a single `U+FFFD` replacement character, which undercounts. For example, two consecutive invalid bytes would produce 1 replacement char instead of 2. You must count 1 char per invalid byte by iterating manually and validating UTF-8 byte sequences.

### Cross-buffer line length tracking
Maintain a `current_line_chars: u64` counter that persists across read chunks. On `'\n'`, update max and reset. After all input is consumed, do a final max update in the `result()` method to handle the last line if it has no trailing newline.

### `clap` error messages don't match the required format
`clap` v4 generates its own error format for unknown flags, which does NOT match `wc: invalid option -- '<char>'`. You must intercept invalid short flags **before** `clap` parsing — scan `std::env::args()` for any single-char flag not in `{l, w, c, m, L}`, print the custom error, and `exit(2)`. Remember to stop scanning after a `--` argument (everything after `--` is a filename).

## Validation Criteria

### Unit Tests (Rust `#[test]`)
- `Cursor::new(b"a\xff\xcfz")` → chars=4, bytes=4.
  Reason: `a`=1 valid char, `\xff`=invalid leading byte→1 fallback char, `\xcf`=expects continuation byte but gets `z`→1 fallback char, `z`=1 valid char.
- `Cursor::new("a\u{1F600}b".as_bytes())` → chars=3, max_line_length=3 (emoji is one codepoint).
- `Cursor::new("hi\r\nworld\n".as_bytes())` → max_line_length=5.
  Reason: line 1 is `hi\r` = 3 chars (only `\n` splits lines, `\r` counts), line 2 is `world` = 5 chars. max(3,5) = 5.
- `Cursor::new(b"")` → chars=0, max_line_length=0.

### Integration Tests (`assert_cmd` + `tempfile`)
- Verify stdout and exit code 0 for `-m`, `-L`, and `-c -m` (canonical order: chars then bytes).
- Verify stderr for missing file: `wc: <name>: No such file or directory\n`, exit 1, missing file absent from stdout.
- Verify stderr for invalid option: `wc: invalid option -- 'q'\nTry 'wc --help' for more information.\n`, exit 2.
- Large-file streaming test per SPEC §5.2: pipe 1GB+ stream with `-m -c`, assert exit 0.
