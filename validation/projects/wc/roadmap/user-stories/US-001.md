# User Story 001: Project scaffold and domain core

As the planner,
I want a compiling Cargo project with the DDD layer skeleton and domain types,
So that subsequent stories only fill in behavior.

## Requirements

- `Cargo.toml` with crate name `wc`, edition 2021, dependencies as specified in SPEC §1.1.
- `src/lib.rs` with `#![deny(unsafe_code)]` and module declarations for all three DDD layers: `pub mod domain; pub mod application; pub mod infrastructure;`.
- Each layer directory (`src/domain/`, `src/application/`, `src/infrastructure/`) must contain a `mod.rs` that re-exports its submodules via `pub mod` declarations. Without these, Rust will not compile the submodule files.
- `src/domain/count_stats.rs`: the `CountStats` struct as specified in SPEC §2.1, deriving `Debug, Clone, Default, PartialEq, Eq`.
- `src/domain/count_strategy.rs`: the `CountStrategy` trait as specified in SPEC §2.1.
- `src/main.rs`: minimal entry that builds (a no-op `fn main() {}` placeholder is fine for this story).
- `cargo build`, `cargo fmt --check`, `cargo clippy -- -D warnings`, and `cargo test` all exit 0.

## Architectural & Performance Constraints
- `#![deny(unsafe_code)]` at the crate root.
- DDD layer separation per SPEC §2.1.

## Validation Criteria

### Unit Tests
- One smoke `#[test]` in `src/domain/count_stats.rs` (inline `#[cfg(test)] mod tests` block) asserting `CountStats::default()` equals an all-zero struct and that `CountStats { lines: 1, ..Default::default() }` differs from `default()`.

### Build/Lint
- `cargo build` exits 0.
- `cargo fmt --check` exits 0.
- `cargo clippy -- -D warnings` exits 0.
- `cargo test` exits 0.
