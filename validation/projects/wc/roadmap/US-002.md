# User Story 002: Multi-file support with total counts summary

As a CLI user,
I want to run wc on multiple files at once
So that I can see the metrics for each file and get an aggregate total of all files.

## Requirements

### 1. Sequential Processing
- The program must accept multiple file paths as arguments (e.g. `wc file1.txt file2.txt`).
- It must process and output the counts for each file sequentially in the order specified.

### 2. Total Sum Row
- After all files are printed, the program must print an additional line containing the accumulated sums of the active counts, followed by the word `total`.

### 3. Mixing Stdin and Files
- If the argument list contains a mix of file paths and `-`, the program must read from stdin when processing `-`. The output name for that input should be `-`.

### 4. Output Example
Running `wc -l -w file1.txt file2.txt` should output:
```
      10       45 file1.txt
       5       20 file2.txt
      15       65 total
```

### 5. Architectural & Performance Constraints
- **No Unsafe Code:** The code must include `#![deny(unsafe_code)]` at the crate root.
- **DDD & SOLID:** The sequential orchestration of files must reside in the Application layer (e.g., in a usecase struct), maintaining separation from file system I/O and command line formatting.
- **Streaming I/O:** Stream each file sequentially, ensuring that memory usage does not accumulate with the number or size of the files processed.

## Validation Criteria

### Unit Tests (With Mocking)
- Verify the usecase struct accumulates totals correctly when injected with multiple mock file readers.

### Integration Tests (No Mocking)
- Run the compiled binary as a subprocess with multiple files.
- Verify correct calculation and formatting of the `total` row.
- Verify mixed file and stdin (`-`) scenarios.
