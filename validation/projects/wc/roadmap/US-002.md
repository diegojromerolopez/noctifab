# User Story 002: Core wc counting (lines, words, bytes) for a single file or stdin

As a CLI user,
I want to count the number of lines, words, and bytes in a file or from standard input,
So that I can analyze the basic size metrics of my text input.

## Requirements

### 1. Basic Counting Options
The program must support `-l`/`--lines`, `-w`/`--words`, `-c`/`--bytes` flags per SPEC §3.1. Short flags may be bundled (e.g. `-lw`).

### 2. Default Behavior
If no flags are specified, default to lines + words + bytes (equivalent to `-l -w -c`).

### 3. Input Sources
- **Single File:** e.g. `wc file.txt` — print counts followed by the filename.
- **Stdin:** If no files given or filename is `-` — print counts only (no filename, no trailing space).

### 4. Output Formatting
Per SPEC §3.3: counts in canonical order `lines, words, bytes` (filtered to active flags, independent of flag order on the command line), each formatted `{:>7}`, separated by a single space; filename preceded by a single space if shown.

### 5. Architectural & Performance Constraints
- `#![deny(unsafe_code)]` at the crate root.
- DDD & SOLID per SPEC §2.1. The use case must receive input via `dyn Read` (DIP).
- Streaming I/O: buffered reading with fixed-size chunks (e.g. 64KB) for O(1) memory.

## Implementation Hints

### Single-pass counting
Implement a single `StreamCounter` struct that counts lines, words, and bytes in ONE pass. Do not create separate strategy implementations per metric — a single pass is required for large-file performance.

### Word counting and Unicode whitespace
SPEC §3.4 defines whitespace as Rust `char::is_whitespace()` (Unicode-aware). For pure ASCII input this is straightforward. For multi-byte UTF-8, you need to decode bytes into chars to correctly detect Unicode whitespace characters.

### `readers.rs` purpose
This module provides a factory function that takes a filename string and returns a `Box<dyn Read>` — opening a file for regular paths, or returning stdin for `-`. Do not add buffering here; the counter applies its own.

## Validation Criteria

### Unit Tests (Rust `#[test]`, no mocking framework)
- Test `StreamCounter` directly with `std::io::Cursor::new(b"...")` and assert exact `CountStats` fields.
- Cases (assert these exact values):
  - `b""`           → lines=0 words=0 bytes=0
  - `b"\n"`         → lines=1 words=0 bytes=1
  - `b"hello world"` → lines=0 words=2 bytes=11
  - `b"a  b\n\nc\n"` → lines=2 words=3 bytes=8
  - `b"  \n  \t\n"`  → lines=2 words=0 bytes=6

### Integration Tests (`assert_cmd` + `tempfile`, no mocking)
- Use `Command::cargo_bin("wc")` + `tempfile::NamedTempFile`.
- Assert byte-exact stdout for: file default, stdin default, `wc -l file`, `wc -w -c file` (canonical column order: words then bytes regardless of flag order).
- Assert exit code 0 for all happy cases.
- Large-file test per SPEC §5.2: pipe 1GB+ stream, assert exit 0 and wall-time < 60s.
