# User Story 000a: Project scaffold and domain core

As the planner,
I want a compiling Cargo project with the DDD layer skeleton and domain types,
So that subsequent stories only fill in behavior.

## Requirements

- `Cargo.toml` with crate name `wc`, edition 2021, deps per SPEC §1.1 (clap v4 derive; `assert_cmd`, `predicates`, `tempfile` as dev-dependencies only).
- `src/lib.rs` with `#![deny(unsafe_code)]`.
- Module files under `src/domain/`, `src/application/`, `src/infrastructure/` (empty stubs that compile).
- `src/domain/count_stats.rs`: `pub struct CountStats { pub lines: u64, pub words: u64, pub chars: u64, pub bytes: u64, pub max_line_len: u64 }` deriving `Debug, Clone, Default, PartialEq, Eq` (Default = all 0).
- `src/domain/count_strategy.rs`: `pub trait CountStrategy { fn count(&mut self, reader: &mut dyn std::io::Read) -> std::io::Result<()>; fn result(self) -> CountStats; }`
- `src/main.rs`: minimal entry that builds (can be a no-op `fn main() {}` placeholder for this story).
- `cargo build`, `cargo fmt --check`, and `cargo clippy -- -D warnings` exit 0.
- `cargo test` (no functional tests yet) exits 0.

## Architectural & Performance Constraints
- `#![deny(unsafe_code)]` at the crate root.
- DDD layer separation per SPEC §2.1 (domain has no external deps; application depends on domain traits; infrastructure depends on application).

## Validation Criteria

### Unit Tests
- One smoke `#[test]` asserting `CountStats::default()` equals an all-zero struct and that `CountStats { lines: 1, ..Default::default() }` differs from `default()`.

### Build/Lint
- `cargo build` exits 0.
- `cargo fmt --check` exits 0.
- `cargo clippy -- -D warnings` exits 0.
- `cargo test` exits 0.
