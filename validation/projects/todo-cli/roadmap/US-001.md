# User Story 001: Task model, Add and List

As a user,
I want to be able to add new tasks to my TODO list and list them
So that I can keep track of what I need to do.

## Requirements

### 1. Project Scaffold & Task Model
- `go.mod` (module `github.com/noctifab/todo-cli`, Go 1.22+).
- `internal/task/entity.go`: `Task` struct with fields per SPEC §2.2 (`ID int`, `Description string`, `Completed bool`, `CreatedAt time.Time`, `CompletedAt *time.Time`).
- `internal/task/repository.go`: `Repository` interface (`Add`, `List`, `GetByID`, `MarkCompleted`, `Delete`, `Save`, `Load`) plus `ErrNotFound` sentinel.
- `internal/storage/jsonrepo.go`: JSON-file implementation using an injected `Clock` (default `time.Now().UTC()`) and `FileSystem` interface for testability.
- `cmd/todo/main.go`: composition root wiring the JSON repository, CLI dispatch, and `os.Stdin`/`os.Stdout`.
- `Makefile` with a `test` target (`go test -v ./...`).

### 2. Adding Tasks
- Command: `todo add "<task description>"` (release binary named `todo`; tests invoke it via `go build -o /tmp/todo ./cmd/todo` then run `/tmp/todo ...`).
- Output: `Added task: "<task description>" (ID: <id>)`
- Behavior: Appends a task to `todo.json` with an auto-incrementing integer ID starting at 1 (`max(existing IDs) + 1`), `Completed=false`, `CreatedAt` = injected `Clock` now (RFC3339-UTC with `Z` suffix). Empty/missing description → exit code 2, stderr `todo: missing task description`, no file write.

### 3. Listing Tasks
- Command: `todo list`
- Output: byte-exact per SPEC §2.5:
  - Header: `ID  Status  Description  Created At\n`
  - Data rows: `<id>  [< >|<x>]  <description>  <YYYY-MM-DD HH:MM>\n` (two-space separators; `Created At` in local time as `2006-01-02 15:04`).
  - Empty: `No tasks found.\n`, exit 0.
- Tests may assert against the literal expected string; do not implement pretty-printing or column alignment beyond the fixed two-space separators.

### 4. Storage
- Save tasks in `todo.json`. Path resolution precedence: `--file` flag > `TODO_FILE` env > `./todo.json` (per SPEC §2.2). `--file` may appear before or after the subcommand keyword. Initially absent file is treated as empty for `add`/`list`; malformed JSON → exit 1, stderr `todo: corrupt file: <path>`.

## Architectural & Performance Constraints
- DI: all collaborators (Repository, Clock, FS, writers) constructor-injected. No file exceeds 500 lines.
- Performance: all operations must complete in < 100 ms wall-clock for a 10,000-task file (read-once/write-once permitted; no in-memory caching required).

## Validation Criteria

### Unit Tests (internal/...)
- `entity_test.go`: `NewTask` assigns next id and `Completed=false`, `CompletedAt=nil`.
- `jsonrepo_test.go`: with an in-memory `FileSystem` and a fake `Clock` returning a fixed time, `Add` then `List` round-trips the same task verbatim; file contents equal expected JSON; concurrent `Add` calls produce ids 1,2,3 even if the file is absent initially.
- `add_test.go`/`list_test.go`: inject a fake repo returning canned data, assert exact stdout strings and exit code 0.

### Integration Tests (tests/)
- Build the binary; run in a tempdir; assert `add "Buy milk"` prints `Added task: "Buy milk" (ID: 1)` and exit code 0; assert `list` prints the exact header + data row per SPEC §2.5; assert `list` on empty dir prints `No tasks found.` and exits 0; assert `todo.json` exists and parses back to one task.
- Assert byte-exact output and exit code 0 for `add` with quotes/spaces in the description.
